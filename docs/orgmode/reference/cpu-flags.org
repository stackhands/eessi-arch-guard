* CPU flags

The processor flags each x86_64 target of the European Environment for Scientific Software Installations (EESSI) needs, and which of them =eessi_archdetect.sh= and eessi-arch-guard check.

** The waitpkg check

=eessi_archdetect.sh= gives a CPU a target when the CPU has the flags of that target's line in =eessi_arch_x86.spec=.
The guard drops a candidate whose last path part, with =-= read as =_=, is one of these, when a processor the task may run on lacks =waitpkg=:

#+begin_example
alderlake arrowlake arrowlake_s clearwaterforest diamondrapids grandridge graniterapids
graniterapids_d novalake pantherlake sapphirerapids sierraforest tremont
#+end_example

- They are the GCC =-march= targets whose instruction set includes =PTA_WAITPKG= in =gcc/config/i386/i386.h=: those of GCC 15.2.0, and =novalake= from GCC 16.
- The flags are those of the =flags= lines of =/proc/cpuinfo=, or of =EESSI_PROC_CPUINFO=, limited to the processors the task may run on; a flag counts only when every one of them has it.
  When the file cannot be read, no processor has the flag.
- No other flag is checked beyond the specification.

** Flags the specification leaves unchecked

GCC's =-march= for a target uses more flags than its specification line asks for.
A CPU that lacks one of the others still gets that target, =waitpkg= aside.
The lists name each target's flags under GCC 15.2.0 by their =/proc/cpuinfo= names; where those differ from GCC's, =pni= is SSE3, =abm= is LZCNT, =bmi1= is BMI, =pclmulqdq= is PCLMUL, =rdrand= is RDRND, =3dnowprefetch= is PREFETCHW and =sha_ni= is SHA.
=avx512vbmi= and =avx512ifma= have no underscore.
=PTA_64BIT=, =PTA_NO_SAHF= and =PTA_EVEX512= have no flag in =/proc/cpuinfo= and are left out, as is =avx10_1=, which =graniterapids= gains after GCC 15.2.0.

- =icelake= is compared with =-march=icelake-server=.
- =graniterapids= has no specification line of its own: =eessi_archdetect.sh= turns a =sapphirerapids= match into =graniterapids= for a CPU of family 6, model 173 or 174, so the flags checked are those of =sapphirerapids=.
- =graniterapids-d= has no specification line; its one flag beyond =graniterapids= is =amx_complex=.
- =alderlake=, =tremont=, =sierraforest=, =grandridge=, =arrowlake=, =arrowlake-s=, =clearwaterforest=, =pantherlake=, =diamondrapids= and =novalake= have no specification line, and =eessi_archdetect.sh= does not choose them from flags.
  When a candidate names one of them, the guard checks =waitpkg= and none of its other flags.
