* Install the prolog

Install eessi-arch-guard as the Slurm =TaskProlog= of a cluster whose compute nodes have more than one CPU or GPU type.
After that, a task that inherits the European Environment for Scientific Software Installations (EESSI) loaded for another type gets it loaded again for its own node, before its program starts, and every other task is left as it is.

** Before you start

- Root on the compute nodes, or on the image they boot, and on =slurm.conf=.
- =/usr/bin/python3=, Python 3.9 or newer, and =bash= on every compute node.
  The guard needs nothing outside Python's standard library.
- EESSI on the compute nodes, as on the login nodes.
  The guard runs the =eessi_archdetect.sh= of the loaded EESSI version and the Lmod named by =LMOD_CMD= in the task's environment.
- No =TaskProlog= in =slurm.conf= yet; with one, the guard runs it first, as in [[file:configure.org][Configure the guard]].
- A checkout of the repository:

  #+begin_src bash
  git clone https://github.com/stackhands/eessi-arch-guard.git
  cd eessi-arch-guard
  #+end_src

** Steps

1. Copy the guard to the same path on every compute node, owned by root and executable:

   #+begin_src bash
   sudo install -m 755 src/eessi_arch_guard.py /usr/local/sbin/eessi-arch-guard
   #+end_src

2. Check that the copy starts Python in isolated mode, and that it runs:

   #+begin_src bash
   head -n 1 /usr/local/sbin/eessi-arch-guard
   /usr/local/sbin/eessi-arch-guard --version
   #+end_src

   #+begin_example
   #!/usr/bin/python3 -I
   0.2.0
   #+end_example

   =-I= makes Python ignore =PYTHONPATH= and the other =PYTHON= variables, the user's site packages and the directory the file is in.
   The prolog runs as the job's user, with the job's environment, so none of those may change which code it runs.
3. Name the copy in =slurm.conf=:

   #+begin_example
   TaskProlog=/usr/local/sbin/eessi-arch-guard
   #+end_example

   Then have =slurmd= on every node read the changed file, as for any other =slurm.conf= change.
   Slurm starts a task prolog with no arguments, so the guard runs with its defaults.
4. If users run =eessi-arch-guard --shell= on the login nodes, install the package there too, for example into a virtual environment.
   On Ubuntu, =python3 -m venv= needs the =python3-venv= package:

   #+begin_src bash
   sudo apt-get install -y python3-venv
   sudo python3 -m venv /opt/site/software/eessi-arch-guard
   sudo /opt/site/software/eessi-arch-guard/bin/python -m pip install .
   /opt/site/software/eessi-arch-guard/bin/eessi-arch-guard --version
   #+end_src

   #+begin_example
   0.2.0
   #+end_example

   The command this installs starts Python without =-I=.
   It serves =--shell=; the =TaskProlog= stays the file from step 1.

** Check that it worked

Run the copy the way =slurmstepd= runs it, with no arguments, in an environment without EESSI:

#+begin_src bash
env -i PATH=/usr/bin:/bin /usr/local/sbin/eessi-arch-guard; echo "exit $?"
env -i PATH=/usr/bin:/bin EESSI_ARCH_GUARD_VERBOSE=1 /usr/local/sbin/eessi-arch-guard; echo "exit $?"
#+end_src

#+begin_example
exit 0
EESSI is not loaded
exit 0
#+end_example

Without EESSI there is nothing to compare, so the guard prints nothing and exits 0.
=EESSI_ARCH_GUARD_VERBOSE=1= makes it say why on stderr.

In a job whose task runs on the node type EESSI was loaded on, the guard prints nothing.
On a node of another type, the task's output starts with a line such as

#+begin_example
eessi-arch-guard: reloaded modules for x86_64/amd/zen2 (loaded for x86_64/amd/zen4)
#+end_example

and =EESSI_ARCH_GUARD_RELOADED= in the task's environment holds the same pair, =x86_64/amd/zen4->x86_64/amd/zen2=.
Only local task 0 of each node prints the line; every task gets the variable.

** If it fails

| Message                                                                                  | Cause                                                                                                   | What to do                                                                                                                                 |
|------------------------------------------------------------------------------------------+---------------------------------------------------------------------------------------------------------+--------------------------------------------------------------------------------------------------------------------------------------------|
| =/usr/local/sbin/eessi-arch-guard: cannot execute: required file not found=, run by hand | The node has no =/usr/bin/python3=; every task on it fails to start.                                    | Install Python 3.9 or newer there, or remove the =TaskProlog= line until then.                                                             |
| =/usr/local/sbin/eessi-arch-guard: Permission denied=, run by hand                       | The copy is not executable; every task on the node fails to start.                                      | Install it again with =-m 755=.                                                                                                            |
| No line and no =EESSI_ARCH_GUARD_RELOADED= in a task that ran on another node type       | =slurmd= has not read the changed =slurm.conf=, or the submitting environment has =EESSI_ARCH_GUARD=0=. | Check =scontrol show config= for =TaskProlog=, and the job's environment.                                                                  |
| =eessi-arch-guard: ... environment left as it was=                                       | A reload was needed and could not be made.                                                              | The rest of the line names the cause, and [[file:read-a-failure.org][Correct a failed reload]] the correction; the task ran with the environment it was submitted with. |
